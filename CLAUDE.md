# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project shape

Sailor CMS is a template-driven headless CMS that installs into other SvelteKit projects (`npm install github:jonkristian/sailorcms` → `npx sailor core:init`). This repo is both the library source _and_ a working dev instance of it — the `src/lib/sailor/` tree is what gets copied/imported into consumer projects.

Status: 0.8.x, experimental/beta. Uses experimental SvelteKit remote functions and Svelte 5 async components.

## Commands

- `bun dev` — dev server on :5173, admin at `/sailor`
- `npm run check` — svelte-check typecheck (use this to validate TS changes; there is no test runner wired up)
- `npm run lint` — prettier check + eslint
- `npm run format` — prettier write
- `npm run build` — production build (adapter-node)
- `npx sailor db:update` — regenerate schema + types + apply migrations from `templates/`. **Run after any template change.**
- `npx sailor <cmd>` or `bun cli/index.js <cmd>` — full CLI (`db:*`, `users:*`, `files:*`, `core:*`).

For UI-facing changes, run the dev server and exercise the feature — there's no test suite.

## Path alias

`$sailor` → `src/lib/sailor` (declared in `svelte.config.js`). Prefer it over relative paths when importing across the sailor library.

## Architecture — the zones

### `src/lib/sailor/` — the CMS library

- **`templates/`** — user-edited template definitions: `blocks/`, `collections/`, `globals/`, `settings.ts`. These are the _input_ to schema generation.
- **`generated/`** — **never edit by hand.** `schema.ts`, `types.ts`, `fields.ts`, `settings.ts`, `block-groups.ts`, `icons.ts` are regenerated by `npx sailor db:update`. Hand edits are lost.
- **`core/`**
  - `auth.ts` (client) + `auth.server.ts` (server) split. Better Auth mounted under `/sailor/api/auth`. `baseURL` + `trustedOrigins` come from `PUBLIC_BASE_URL` (read via `$env/dynamic/public`), defaulting to `http://localhost:5173`.
  - `db/` — Drizzle adapter; backend picked from `DATABASE_URL` (SQLite/Turso/Postgres). Only SQLite and Postgres are supported (`DatabaseType`).
  - `hooks/sailor-hooks.ts` — invoked from `src/hooks.server.ts`; wires auth + CMS route handling.
  - `services/`, `settings/`, `editor/`, `files/`, `content/`, `types/`, `ui/`, `utils/`.
- **`remote/*.remote.ts`** — all server RPC endpoints. Use `command`/`query` from `$app/server`. Gated by `kit.experimental.remoteFunctions: true`.
- **`composables/`**, **`utils/`** — shared Svelte 5 runes helpers and content/file utilities.

### `src/routes/`

- `sailor/` — admin UI routes (served at `/sailor`, `/sailor/collections/[slug]`, `/sailor/api/auth/*`, etc.).
- `(site)/` — the consumer project's public-facing site routes.

### CLI

`bin/sailor.js` → `cli/index.js` (commander). Each command registers from `cli/tools/` (`cms-init`, `cms-update`, `db-update`, `db-generate`, `db-backup`, `db-restore`, `db-seed`, `users-manage`).

## Conventions and gotchas

- **Schema workflow:** edit `templates/` → run `npx sailor db:update` → commit both the template change and the regenerated `generated/` files plus any new migration under `drizzle/`. Do **not** write Drizzle schema or migrations by hand.
- **Remote functions** have non-trivial call-context rules (`.run()` vs awaiting directly differs between server load, universal load, components, and event handlers). Check `src/lib/sailor/remote/*.remote.ts` for established patterns before adding one.
- **Experimental features are intentionally on** (`svelte.config.js`): `kit.experimental.remoteFunctions` and `compilerOptions.experimental.async` (the latter is required because SvelteKit remote functions use `hydratable()` internally — turning it off makes `query()` / `command()` throw `experimental_async_required` at runtime). Don't "fix" them off.
- **Env vars:** anything needed on the client must use the `PUBLIC_` prefix and be read from `$env/dynamic/public`. Server-only secrets come from `$env/dynamic/private` (which excludes `PUBLIC_*`).
- **Hands off:**
  - `src/lib/sailor/generated/` (regenerate instead)
  - `src/lib/components/ui/` — shadcn-svelte components, don't modify unless explicitly asked
  - `sailor.sqlite` and other db artifacts
- **Admin UI vs public site:** `/sailor/*` is the CMS admin; `(site)/*` is the consumer's frontend. Don't cross the streams.
